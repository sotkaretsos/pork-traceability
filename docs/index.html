Pork Traceability

The Solidity contract of Blockchain Traceability Architecture for Pork in Food Service runs here, in your browser. It follows pork from the slaughterhouse to a souvlaki restaurant and answers the consumer's two questions: where the meat came from, and whether it was kept and handled safely.

  • Solidity 0.8.24 · London EVM
  • One contract, four modules
  • Runs locally
Project repository Simplified model live demo (v1.0.0) Third-party licenses

1 Replay the supply chain

Five pigs are slaughtered and inspected; four carcasses become cuts, gyros cones and skewers, and a souvlaki restaurant serves them as a lunch lot and a dinner lot. On the evening of the service the authority recalls one carcass. Every step is a transaction on the contract.

        2 Try to break the rules

        Each attempt is sent to the deployed contract on a snapshot of the chain and rolled back afterwards, so the replayed chain stays intact. The tag names the rule that stops it.

        3 How this page works

        Same bytecode as the repository

        The page loads the bytecode compiled from the repository's Solidity sources (Solidity 0.8.24, intermediate-representation pipeline, 200 optimizer runs, London rules) and executes it with the EthereumJS virtual machine. The verification page is read with the contract's own view functions: getProvenance, effectiveStatus, hasBreachInAncestry and isRecalled.

        A private test chain in this tab

        Chain ID 31337, zero gas price and one block per transaction, as on the permissioned Hyperledger Besu network of the design. Block timestamps follow the dates of the scenario. Accounts come from the public Hardhat test mnemonic; organisation names and approval numbers are fictitious, and nothing leaves your browser.

        Run it yourself

        Clone the repository, then run npm install --legacy-peer-deps and npm test for the 31 contract tests. The same scenario runs in Node with cd demo && npm ci && npm run test:node, and npm run build rebuilds this page.
